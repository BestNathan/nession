Design decisions & validation

This is a candidate for #3142, not deployed Nession. Try each operation from the Session/Project area and compare Web and App without refreshing.

Overlay families

  1. Anchored: menu, Select, Popover stay close to the trigger and remain usable over a parent dialog.
  2. Compact: rename and destructive confirmation ask only one focused question.
  3. Standard/Wide: New Session and New Project have explicit form groupings; only the body scrolls.

Experience ownership

  1. Web keeps the current shell visible behind a restrained scrim and centered dialog.
  2. App uses a short Attach sheet, full-height New Session / Project configuration, and one Back owner.
  3. Switch Web → App → Web; the selected experience (not browser window size) changes the actual composition.

Negative/edge paths

  1. Enable Long path, open New Project and compare Corrected / Legacy approximation at top, middle and bottom. Header must fully cover the top; Footer must meet the bottom.
  2. Open New Session → Location to inspect anchored child choice, full path wrapping and Escape priority.
  3. Enable Offline/Invalid, attempt submit, Cancel, reopen and inspect state. Destructive operation requires explicit confirmation.

Fidelity & evidence

The Legacy mode is an illustrative source-based approximation for #3298, not a measured production screenshot. The corrected mode keeps Header and Footer independent of scrolling Body. Layout/terminology follow #3089's shipped intent and current Nession design documents. This mock intentionally does not reproduce every React control implementation or server state. Portal, focus, touch and layout must be proven in production by source-aligned Chromium Cases. Browser/publication proof for this artifact is tracked separately.
