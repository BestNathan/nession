为什么 UI 一致性不能只靠 Token？

布局也是产品行为：同一个角色必须拥有一致的宽度、排列、滚动、响应式与操作区域，即便每一行 Tailwind 都是合法语法。

① Experience owns the frame

Web 使用 Sidebar + Workspace work surface，App 使用单一页面级 Back/Header + capability content。只有上层决定工作区尺寸、滚动祖先和 Web/App 布局；能力组件不重复构建外壳。

② Semantic layout owns repeated geometry

详情页的内容宽度、表单控件高度/对齐、Files split 或 App push、内容滚动与操作栏保持一致。不是对每个 flex 做禁用，而是复用稳定布局 recipe。

③ Local composition still stays flexible

cn('flex min-w-0 flex-col', ...) 可以安全用于组件内部的内容排列；当它改变 Workspace host 的 flex sizing、滚动或跨端结构时，需要使用受约束的 owner。

④ Gate must check both static and rendered

静态负例检测未经授权的 host 尺寸/滚动/私有间距。Chromium Case 进一步测量 scrollWidth、滚动祖先、对齐、App header 数量和可访问操作区。这里的只读数值是原型 DOM 测量，不是生产验收。
