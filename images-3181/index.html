Functional design & verification

完全确定性的 mock：没有真实 Registry、Git 构建、blob 下载、Agent 缓存或 Sandbox 执行。

Ownership / information architecture

  1. Server 拥有 Registry、Alias 与 Blob；Workspace 只发现并操作 Images capability，没有永久 Images 侧栏项。
  2. Project 只保存 image reference；拥有独立的单镜像选择流程，构建成功后必须显式选择 Ready 镜像，失败不改变旧引用。
  3. Sandbox 拥有独立的多镜像组合流程（选择 + target + mode），不复用 Project 的选择器/引用模型；不拥有镜像字节。
  4. Agent 仅消费 scoped Digest；缓存 absent/preparing/verified/failed 与 Server Ready 分开呈现。

Try these paths

  1. Workspace 无 Session：搜索、翻页 235 张图、查看 Digest/Alias/来源；切到 empty 或 unavailable 查看真实空/不可用状态。
  2. Context → Project：Select Project image 是 Project 独立的单镜像流程；Build from Git Source 成功→Use this image，或 buildfail→旧引用保持不变。
  3. Context → Sandbox：Add image 打开 Sandbox 独立的组合流程，选择镜像并配置 target/mode 后加入；aliasshift 时旧选择保持 pinned Digest。
  4. Web 1180/1024 ↔ App 390/375：App 单 Back 在 capability→list→detail 及各自选择流程间返回；键盘可操作。

Decided product boundaries

已确认（2026-11-11）：Images 不增加永久全局侧栏项；Project 与 Sandbox 的镜像流程彼此独立，不共用 Picker/引用模型。Sandbox 保留独立 target 与 read-only/overlay，选择时固定 Digest；Alias 变化不改变已固定的 Sandbox/Session 镜像身份。Server Ready 不等于 Agent ready。App 使用 capability 入口 + 单 Back/标题层级。超过 200 张时必须可完整分页，而不是静默截断。

Verification limitations

本页是 mock；CSS/布局基于 WorkspaceShell、WorkspacePanel、AppPageHeader 与生成的 token 语义近似。真实 API、授权、Digest 校验、Agent 缓存与 Sandbox 执行必须由后续实现与 Acceptance Cases 证明。Pages 发布 SHA 与真实 Chromium 交互另行记录。
