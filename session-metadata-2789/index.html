Function design & verification

上半部分是真实尺寸的产品交互模拟；下面才是设计决议、范围与证据，不在 Workspace 内展示开发说明。

试用路径

  1. 在 Workspace 的 Session 视图点「编辑信息」；修改 Title / Description / Tags。
  2. 保存后观察 Session 列表标题同步改变，tmux 名和 Session ID 不变。
  3. 再次编辑并「取消」，检查草稿丢弃；切换 Session 时检查未保存确认。
  4. 切换 No metadata、Offline、Conflict、Recreated 观察回退及错误处理。
  5. 从 Terminal 返回 Workspace；App 按 Back 保留 Session 上下文。

明确的产品边界

Title 为展示别名；Session ID、Agent、tmux name、实时 cwd 与 foreground command 不通过元信息编辑。Tags 为简单索引，不生成永久导航。结束与重建同名 Session 不继承旧元信息。

不包含 Input History、Output History、MCP stream、Agent 调度或 AI 自动打标签。

视觉参照

依据 docs/design/composition.md、SessionItem、SessionDetails、WorkspaceShell、AppPageHeader 及 design/generated/web.css 的语义色与排版角色。Web 保持侧栏 + 工作面，App 使用层级与底部 Capsule。

这是 HTML 近似，不包含生产 React/shadcn、xterm 字形计算和实际手势。

证据与限制

所有 Session、存储 revision、冲突和离线数据是内存模拟，无任何网络调用、真实持久化或生产权限校验。页面刷新重置；外部 Reset 重播初始状态。

独立测试需检查桌面/移动点击、键盘可访问、非法输入、冲突、取消、滚动、链接和控制台。Pages SHA 以实际清单读回为准。
