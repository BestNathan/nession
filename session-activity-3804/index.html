交互决策与验收场景

产品内部只有统一的 Session 活动提示；测试事件、归属与协议细节保留在外部评审区域。真实 Server/Agent / CLI 状态同步属于 #3800–#3804 的后续实现。

01 · 列表信息层级

第一行：Session 名称 + 左侧固定大小活动符号。第二行：workload · Agent · recency。Working 是有动效的细小弧线；Idle 是弱轮廓；Unknown 显示问号；Needs input 才增加第三行请求注意。所有状态占位宽度一致，避免列表跳动。

所有图标都有无障碍文本；没有用一个彩色点同时表达联网、Session 存活、连接与活动。

02 · 状态与连接独立

选 “Agent offline” 后，原有 Working 不再宣称是实时状态，行显示 Unknown + Agent unreachable。选 “Re-sync” 才恢复新的权威状态。“Stale event” 不覆盖当前值，也不更改 recency。

动效遵循 reduced-motion；后台无输出的命令不自动变成 Idle。

03 · Web 与 App 真实导航

  1. 在 Web 的 Sidebar 选中 Session，主区域切换当前 Terminal。
  2. 切换 App 390/375：出现独立 Sessions 层，而不是压缩后的 Sidebar；点 Session 进入 Terminal，再从左上角回到 Sessions。
  3. 每行尾部的 “···” 允许查看详情、编辑标题、配置 attach、模拟删除，不会自动选中目标。

04 · 原型与真实实现的边界

Mock：固定 Sessions、状态变化、实例代际、原型中的对话结果与操作反馈。没有连接真实 GitHub Actions、tmux、Claude/Codex、Server 或用户数据；Terminal 使用纯文本近似，不是 xterm。

Web 主体与 App 的空间层级依据现有 main 组件；像素、字体、滚动和细节仍需 Chromium 与生产 Fixture 对照后确认。
