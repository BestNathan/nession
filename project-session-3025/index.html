Functional design & verification

两种创建方法属于一个 Project。图中 Agent、构建、缓存、Mount、Session 均为演示数据，不对外发起 API 请求。

完整可点流程

  1. Web Sidebar 的 Projects → Nession，或 App Sessions 层的 Projects → Nession，点击后进入不依赖 Session 的 Project 详情；检查 Git Source、MacBook 位置和全局 EROFS 引用。
  2. 点击「新建 Session」→ Existing → MacBook → 填写名称并提交 → 返回 Terminal。
  3. 再打开 Project → Managed → 选 Linux 节点、Source Digest 和 Node/Rust →「准备镜像」→「创建 Session」。
  4. 测试外部输入「下载失败」「Sandbox 不可用」和「节点离线」，验证错误提示、保留填写内容、不能绕过 Sandbox。
  5. 在 Project 中「构建 EROFS」产生新的不可变 Digest，现有 Session 保持原 Digest。
  6. Terminal 中点击 Project Capsule → Peek → Project Workspace 能力 → 完整 Project 详情；修改、解除或关联 Project 后切换 Session，检查不同 Session 的上下文不串联、返回位置保留。
  7. Web 1180 → App 390 → Web 1180；测试 Sessions → Project detail → Back → Sessions、原 Session 返回，以及无 Session 时 Project 仍可进入。

职责边界

Project #3021 定义 Source、Locations、Session 默认值；#3082 定义 Session 显式项目归属与 Project Capability 感知。独立 EROFS Manager #3022 构建、存储及分发共享镜像。Agent #3023 负责 PVC 缓存，Sandbox #3024 只 Mount。Session #3025 固定最终 Agent、镜像版本和 ENV Binding。

不引入 ProjectEnvironment 对象，不分 ExistingProject / ManagedProject。

信息架构与视觉

Web 候选：WebLayout → Sidebar(Agents、扁平 Sessions、Projects) → 主区域 ProjectDetail，项目详情独立于 Session Workspace。App 候选：Sessions 层增加 Projects 区域，点击进入独立 ProjectDetail pushed depth，唯一 AppPageHeader/Back 由宿主负责。Session 的 Terminal/Workspace 继续由现有 Capsule/Workspace Shell 负责，但增加与聚焦 Session 关联的 Project Peek 和能力视图，且不新增第二个全局 Header。
