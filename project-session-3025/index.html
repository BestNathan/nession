Functional design & verification

两种创建方法属于一个 Project。图中 Agent、构建、缓存、Mount、Session 均为演示数据，不对外发起 API 请求。

完整可点流程

  1. 查看 Project Git Source、MacBook 已有位置和全局 EROFS 引用，点击「项目设置」保存 Source ref 和路径。
  2. 点击「新建 Session」→ Existing → MacBook → 填写名称并提交 → 返回 Terminal。
  3. 再打开 Project → Managed → 选 Linux 节点、Source Digest 和 Node/Rust →「准备镜像」→「创建 Session」。
  4. 测试外部输入「下载失败」「Sandbox 不可用」和「节点离线」，验证错误提示、保留填写内容、不能绕过 Sandbox。
  5. 在 Project 中「构建 EROFS」产生新的不可变 Digest，现有 Session 保持原 Digest。
  6. Web 1180 → App 390 → Web 1180；App 保持一个 PageHeader/Back，无嵌套桌面侧栏。

职责边界

Project #3021 定义 Source、Locations、Session 默认值。独立 EROFS Manager #3022 构建、存储及分发共享镜像。Agent #3023 负责 PVC 缓存，Sandbox #3024 只 Mount。Session #3025 固定最终 Agent、镜像版本和 ENV Binding。

不引入 ProjectEnvironment 对象，不分 ExistingProject / ManagedProject。

信息架构与视觉

验证与限制

在此前 GitHub Task 中实测过 Nession Source EROFS 23.90 MiB、Node+NPM 57.99 MiB、Rust+Clippy 246.47 MiB；本原型仅引用这些数字，不发生真实下载或 Mount。

Pages 发布 SHA、原型静态检查、真实浏览器体验和生产 Acceptance 是不同证据。
