Interaction & verification contract

Test the user-visible decision, not a simulated backend acceptance result.

Primary walkthrough

  1. Open Project Settings, reorder/add/remove Server ENV references and save.
  2. Choose Create Session, inspect effective ENV, switch inherit → custom → none and explicitly create.
  3. Inspect the created Session's independent Binding; reopen Project and edit defaults, then create another Session.
  4. Switch between Web and App widths and use App Back to return without losing work.

Decision & boundary

Project stores ordered Server ENV references, not values. New env_selection_mode distinguishes inherit vs explicit replacement, including empty.

Missing ENV fails visibly at creation; existing Session Binding remains immutable after Project changes. No ProjectEnvironment object or automatic reapply.

What is simulated

Project CRUD, ENV catalog and resolution, Session creation, Binding revision, error/availability and navigation are in-memory fixtures. No real credentials, agent, tmux or API calls.

Appearance approximates main Nession tokens and Project/Session operation-surface grammar, not pixel-matched shipping React.

Device/verification scope

Source-led layout model: Web Sidebar → independent ProjectDetail; App Sessions → ProjectDetail → one depth-owned Header/Back → operation view; Session remains a top-level destination.

Local browser and Pages SHA verification not yet recorded; static mock only.
