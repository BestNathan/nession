Functional design & verification

Product is a deterministic mock. No real home directories, network calls, credentials, runtime installation or MCP execution.

Architecture / ownership

  1. WorkspaceShell owns navigation + dock; AI owns Skills/MCP list/detail and operations.
  2. AppPageHeader has a single Back, returning detail → AI root → Terminal.
  3. Project Skills/MCP are intentionally absent; client extensions own them.

Try these paths

  1. Switch Skills ⇄ MCP and search; AI follows the current Session Agent without any Agent picker.
  2. Select an item, inspect origin and path; unmanaged remove is unavailable.
  3. Install Skill (Git source + SHA), add MCP (HTTP/stdio), Cancel/Confirm and remove a managed entry.
  4. Switch Sessions from the Web Sidebar or external App test fixture; test offline, empty, no Session and App Back.

Semantic constraints

Agent context is inherited from the current Session, not user-selectable or cluster-wide. "Configured" is not "reachable" or "active in client". Installing Skills via a native manager does not imply scripts are safe or Node-free. Unmanaged resources are not mutated implicitly.

Verification limitations

Mock CSS is based on generated token semantics and source-reviewed Workspace/App ownership. Live production fixture parity, real Chromium click-through, mobile rendering, Pages manifest freshness and real integration Acceptance require independent verification.
