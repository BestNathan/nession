Function and verification

The proposal changes sidebar information architecture only; the full Web work surface and Shell ownership remain recognizable.

Proposed hierarchy

  1. Top: shell toggle, New Session, Search.
  2. Middle: flat Session history, time labels, local item overflow.
  3. Bottom: on-demand Agents/location context and independent Server state.

Try the critical path

  1. Select a different Session, then search for one.
  2. Create a Session with explicit submit; try the offline Agent.
  3. Collapse/reopen and inspect the work width.
  4. Switch to Narrow 390; open/close the drawer.

Candidate vs shipped

On current main, Agents occupy the sidebar top; collapse uses a static-summary rail. Here Sessions lead, Agent details are revealed on request, and collapse fully tucks away the column. These changes have not been integrated into production Web.

Visual specification

The live annotated UI Design section above is the primary visual handoff: choose a Sidebar element to inspect computed dimensions, typography and tokens. Canonical tokens remain authoritative. The separate UI-SPEC.md file is supporting detail, not the only way to see the design.

Evidence / gaps

Plain HTML + sanitized fixtures, CSS terminal-text approximation, no live tmux, no persistent Server/Agent state, no real Session creation. Viewport 1:1 is not screenshot/pixel parity. Browser/Pages publish and exact-SHA production Acceptance must be verified independently.
