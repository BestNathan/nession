Functional design & review notes

A visual proposal rather than a second Select implementation. The current-mode approximation follows staging `select.tsx`, not a captured production screenshot. A real approval requires current React Chromium side-by-side comparison and Design Gate evidence.

What changes

  1. Action / short choice: compact, single-line, one focus treatment; Web density does not change without revising its canonical 28px contract.
  2. Resource choice: meaningful title, source/path and quiet status; selected indicator is stable, no competing decorative color.
  3. Popup width: current option width tracks trigger; candidate rich choices can use more usable width, capped by viewport, with wrapping instead of hidden data.

Try the controls

  1. Open Existing Location. Compare title/status/path legibility, selected and disabled rows. Switch Current↔Candidate with the same fixture and target.
  2. Open Agent or Connection Mode for one-line choices. Try ArrowUp/ArrowDown/Home/End, Enter and Escape. Disabled options cannot commit.
  3. Switch to App 390/375 and Dark. Check touch-target space, selected-state contrast and available-height collision. Repeat after enabling Long Paths.

Boundaries

Do not reinterpret every menu row as a card. Status/source metadata belongs only to data that actually has it. The current `popup-menu.md` Web 28px action band / App 44px touch band remains unchanged in the prototype; rich rows are semantically taller. Existing Location may need the width to grow, not the whole dialog.

Fidelity and verification

Source-informed visual mock with sanitized fixtures. DOM hierarchy approximates the New Session dialog in Web and App operation depth; real Base UI positioning, focus trap, keyboard/IME behavior, reduced motion, computed token values and exact pixel parity are not claimed. This prototype has no backend, no successful Session creation, and no production Acceptance.
