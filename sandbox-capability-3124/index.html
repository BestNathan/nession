Images · Information architecture & interaction contract

本次按 Nession 的 ResourceDetail / ConfigurationForm / OperationSurface 三种内容语法重构 Images 管理。产品 UI 由 Sandbox 所属 Workspace 承载；此处是原型评审说明，绝不出现在实际 Session 页面中。所有 Catalog、Build、Agent 与 Tag 数据都是本地模拟。

01 · 信息架构与权责

  1. 入口：Session → Workspace → Sandbox → Images。Images 的 Catalog 全局共享，但不增加全局 Sidebar 目的地；Web 使用 Sandbox 内部左侧局部导航，App 使用同一宿主 Header/Back 下的横向局部导航。
  2. Library / Server：Repository、Tag、Manifest/Index、Config/Layer、来源、依赖闭包、被引用状态。Tag 是可变指针；Image 是不可变 Manifest 身份。Server Catalog 和 GC 是唯一资源所有者。
  3. Builds / Server：新镜像创建、Source 类型、Compose、异步任务、状态、历史与重试。Build 状态由 Server 的持久 Job 记录拥有，不能靠前端定时器推断。
  4. Distribution / 当前 Agent：只观察和准备当前 Session 所属 Agent 的内容缓存。Server Ready ≠ Agent Verified ≠ Runtime Compatible；没有全局 Agent 分发调度器。

02 · Library / ResourceDetail

  1. 一个紧凑列表按 Repository、Status、文本检索过滤；行内展示 Name、Repository / Tag、表示格式、大小与 Server 状态。点击行在同一行下方展开详情，再次点击收起，同时仅展开一个镜像。
  2. 详情按 Identity → Source & Dependencies → References → Availability 分组；Manifest Digest 使用 mono，未知 Config/Index 字段标记为 Unknown，不将 Legacy DTO 中不存在的元数据伪造成已观测。
  3. Tag 操作在当前行内展开 OperationSurface：编辑名称 → Review 旧 Digest / 新 Digest / 影响 → Confirm CAS；Tag Unlink 也必须独立 Review 和 Confirm。并发修改拒绝并允许 Refresh expected Tag 后再次 Review。
  4. Tag 更新、解绑不触碰 CAS Blob、Agent Cache、运行中的 Mount 或 Project/Session pin。当前 Agent 离线时仍允许 Server Catalog 管理；Server 离线则禁止变更。

03 · Builds / ConfigurationForm

  1. “New image” 是本区域唯一主操作，打开有独立标题、Source choice、分组字段、错误提示与提交底栏的配置表单。GitHub、受授权 Server Directory、Compose 为当前 Build Source DTO 支持类型。
  2. Compose 展示有序 Source rows（Image、目标目录、排序、删除、添加），输出可选择 Flattened 或 Referenced。重复 Source、目标重叠、越界路径与不支持的 Referenced 组合会明确拒绝。
  3. Archive / OCI 来源在原型中禁用并标注 pending；底层转换能力不意味着当前 Server Build Submit 协议已支持。需要 #3795 先补齐协议和鉴权。
  4. Build 活动列表展示状态、Stage、Attempt、真实阶段计数与诊断；可以过滤和翻页、查看任务详情、Cancel、Retry。未知 mkfs.erofs 包装进度只显示不确定阶段，不造总体百分比。

04 · Distribution / observed facts

  1. 顶部明确“Agent · nession-dev”，每个 Image 行单独展示 Server 状态与 Agent Cache 状态，不合并成一个 Ready。
  2. 按行展开：Manifest 身份、实际字节进度、校验状态和 Runtime Compatibility；只有 SHA-256 Verified 后才可标记 Agent Cache 可用，而 Runtime 还要检查平台和 Composite mount closure。
  3. Absent、Resumable、Failed 的显式 Prepare / Resume / Retry；Downloading 和 Verifying 只能观察阶段，不允许误报已挂载。
  4. Agent 离线显示 Unknown；Server 离线时不允许开始新资源准备。所有进度与成功均为模拟，原型不发起真实网络或 IO。

05 · Nession 设计语言 / Web + App

  1. Hierarchy: 资源列表优先，不使用卡片墙、统计大屏或独立尾部详情面板。靠留白、分隔线和主次文字表达结构；Read-only 事实不伪装成 disabled Inputs。
  2. Tokens: 语义 Background / Surface / Border / Foreground / Muted，mono 只用于 Digest、ID、技术指标。Radius-Control 用于按钮/输入，Radius-Surface 用于主动展开的 OperationSurface。
  3. Color: 默认 Ready/Verified 为中性事实；只用 warning/error 强调进度阻塞、故障、CAS 冲突。每个区域最多一个主动主操作。
  4. Web: 1180/1024 的资源表格多列排布；App: 390/375 保留宿主唯一 Header，内容折叠为单列，点击/确认保持 44px 操作带；Preview 的实际 CSS px 不缩放。

此版本基于 docs/design/visual-language.md、docs/design/information-architecture.md、docs/design/design-system/patterns/{resource-detail,configuration-form,operation-surface}.md，以及当前 web/src/capabilities/images/ / sandbox/ 的责任边界。
