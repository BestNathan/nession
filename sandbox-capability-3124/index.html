Functional design & verification

原型内的 Agent / Session / Policy / Execution ID 均为合成示例。模拟控制位于产品画布外；切换条件不触发真实进程、隔离、远程调用或持久化。

交互路径

  1. Terminal → Workspace（Web 圆形目的地；App 显式 Workspace 入口）。
  2. Capsule → Sandbox → 查看状态和五个 Policy 维度；展开详情查看 effective mechanisms、digest、execution id。
  3. 切换外部条件 Native / Offline / Unsupported / Recreated：不将 Agent 离线误报为 Native，也不将旧执行报告关联到新实例；Unavailable 不占胶囊槽。
  4. App 在详情深度点击唯一 Back 返回 Sandbox，再返回 Terminal。Web 通过左侧目的地按钮返回 Terminal。
  5. Web 1180 → App 390 → Web 1180；切换 Files/Agent/Sandbox 后当前 Capsule 仍可用且不改变高度。

语义边界

Agent probe 是宿主能支持什么；SandboxExecutionReport 是实际执行了什么；Workspace presence 是产品如何显示。每次点击不是新的 Sandbox 执行。隔离范围是 On-demand initial Pane，不承诺未来新开的 tmux Window/Pane 都被强制隔离。

ENV 属于独立 Session Binding；EROFS 属于 #3022–#3024，Managed 创建属于 #3062，本 Issue 不新增镜像、策略编辑和安全承诺。

UI 所有权

Web：WebLayout → Sidebar + ShellMain → WorkspacePanel → WorkspaceShell → Sandbox view。Sidebar 只有扁平 Session 与 Agent，Sandbox 不再创建二级全局导航。

App：AppLayers（Sessions ← Terminal → Workspace）→ WorkspacePanel 的唯一 AppPageHeader/Back → WorkspaceShell → Sandbox root/detail。Workspace Capsule 在每个深度保留，内部横向滚动；无 Workspace “+” 菜单。

验证范围与限制

页面行为为确定性 mock；样式使用 staging 生成设计 token 的局部快照，未接入 React、WebSocket、Bubblewrap、Seatbelt、cgroup、tmux、真实安全策略。DOM/静态源码核对不等于浏览器验收；真浏览器 / Pages 发布 SHA 需要独立记录。
