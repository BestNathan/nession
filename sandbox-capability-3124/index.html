Design contract & verification

本原型复用 sandbox-capability-3124/ 目录，修订原六个同级策略 Tab 的信息架构。产品预览已收起解释性文字：带点状下划线的关键词可悬停或键盘聚焦查看解释，App 可点击展开；完整设计约束集中放在这里。所有 Image、Build、Workspace 与 Sandbox Enter 仍为确定性 Mock，不调用生产服务。

01 · Sandbox + Images (#3408)

  1. 从当前 Session 进入 Sandbox，查看 Overview。切换 Images → Image Library / Builds / Distribution。Server Ready 与当前 Agent Cache 必须分开表示。
  2. 在 Library 选择 Runtime 或 Toolchain 可跳转 Filesystem。切换同 Server 的另一个 Session，不会生成第二份 Images Registry。
  3. Web 一级导航位于 Sandbox Header 右侧、二级导航在选中管理区的局部 Sidebar；App 内使用紧凑横向导航但不新增第二个 App Back。

02 · Agent Workspaces (#3407)

  1. Session sandbox-review 有 Project Existing Location，默认使用 Agent 上的该目录。切换 Session fix-terminal 后无 Project Location，使用按 Session 名自动分配。
  2. 在 Workspaces 里模拟创建命名资源、同名复用、查看列表及删除确认；Project Location 只引用不删除，Managed Resource 在 Sandbox 退出后仍可列出。
  3. Filesystem 引用 Workspace，Agent 解析实际目录；映射目标隐含为 /workspace。

03 · Filesystem Policy (#3405)

Access：同名目录只读/读写映射（P→P），没有目标输入。Mounts：授权的 EROFS Digest 显式映射到受限目标（Source→Target）。RootFS：独占根挂载，目标隐含 /。Workspace 目标隐含 /workspace。Home 独立于 Workspace。

当前 V1 的 EROFS Root 和任意 filesystem.access 互斥；示意可展示冲突但不能通过预检。工具 Mount 先只允许 /opt/<name>。

04 · 解释性注释的呈现原则

产品视图区：只显示对象、名称、状态、必要的资源来源与路径映射、可操作控件、验证结果和危险操作确认。Hover / focus / tap 才展开概念说明，包括 RootFS 的隐式 /、Mount 的 Source→Target、Access 的 P→P、Workspace 来源与 Home 生命周期。

外部注释区：设计理由、协议尚未发布、权限/数据权责、模拟与真实实现的差异，以及原型验收边界，统一在此页说明或 README 中记录。拒绝原因及操作安全确认仍须留在产品界面，不能藏进帮助提示。

Fidelity & negative states

模拟 Agent 离线、macOS、不支持 cgroup/seccomp、Image Cache absent、没有 Session、预检失败、启动失败、Inside 只读等场景。Shell 结构依据 main 现有 WebLayout / Sidebar + ShellMain → WorkspaceShell 与 AppLayers → one AppPageHeader，候选变化仅在 Sandbox 内部。

Web/App 1:1 尺寸是展示目标，**未声明与生产 UI 的像素完全一致**。Mock 静态自测、真实 Chromium 交互、Pages 发布 SHA 和生产 Acceptance 需独立记录；本页面的模拟按钮不是原生 Kernel/EROFS 验证。
