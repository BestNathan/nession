# Nession 0.x — Remote Control

**Product generation:** Initial product / existing 0.x release line  
**Positioning:** Remote terminal control across devices and compute nodes

## Product proposition

Nession 0.x is a remote-control product for developers and operators who need reliable access to command-line work running on other machines.

The user's primary intent is **to reach a machine and operate its terminal session**. Nession connects remote nodes and keeps terminal sessions available so the user can attach from a Web client or CLI without repeatedly starting the same remote command-line environment from scratch.

> **0.x promise:** Connect to remote execution environments and control persistent terminal sessions from wherever the user is working.

## Primary user experience

- Discover reachable managed nodes without manually opening a separate remote connection for every terminal.
- Create, find, attach to, and manage remote terminal sessions.
- Return to an existing remote session from another client or device, subject to actual connectivity and session state.
- Use a central relay where direct connectivity is unavailable, with direct Agent connectivity where supported.
- Keep infrastructure and access details understandable enough to diagnose a failed connection.

This is a **product target and existing capability family**, not a claim that every reconnect, transport, or multi-device edge case is fully solved in every 0.x release.

## Core product model at this generation

- **Server:** the central discovery and coordination point for Agents and Sessions.
- **Agent:** the node-side endpoint that provides access to remote execution.
- **Session:** a persistent remote terminal work context, currently backed by tmux.
- **Terminal:** the main surface for direct interaction with a Session.
- **Clients:** Web and CLI entry points for managing and attaching to Sessions.

Here, Sessions are mostly approached through remote-control and node-management workflows. They provide the foundation for the broader work-first model in 1.x.

## Boundaries

0.x is **not** defined by:

- a first-class logical Workspace spanning work resources or locations;
- a unified, contextual capability experience around the work;
- a universal AI conversation, task, or agent-orchestration model;
- hiding all execution topology from the user.

Those may become relevant later, but they are not retroactive obligations of the 0.x positioning.

## Product outcome

A user can identify a remote node, start or find a persistent Session, and operate it through Nession from an appropriate client. When reachability is interrupted, the product should distinguish loss of connection from destruction of the remote work; stronger continuity and context-preserving interactions become the explicit 1.x product focus.

Implementation and current release behavior are documented by the [README](../../README.md), issues, code, and release artifacts, rather than by this generation definition.
